Why it matters

The tests passed. The bug shipped anyway.

GPT-4o wrote sum_vec = numbers.iter().sum() and called it correct. It passes cargo test. It overflows on [i32::MAX, 1]. A test suite that uses sensible inputs never sees that.

slide 3 / 5 · the answer
03 / 05
The fix

Don’t test it. Prove it for every input.

$ cargo vouch find_max.rs 🔴 BUG find_max: Option::unwrap() on None reachable with input: [] (empty vector)

It checks every input in bounds and hands back the exact value that breaks the function.

What it can’t do

It’s narrow, and I say so in the README.

It proves loop-light functions: arithmetic, indexing, unwraps. On two random crates from crates.io it proved nothing. 6 of 6 functions came back inconclusive, because they parse and iterate. It never fakes a pass.
